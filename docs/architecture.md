# Архитектура

## Обзор

Проект реализует ACPI-EC (эмулятор контроллера батареи) на STM32F103
с обновлением прошивки по I2C (OTA). Состоит из двух образов —
загрузчика и приложения — и хостовой утилиты прошивки.

```
Хост (RV1106 / RPi / PC)                STM32F103
┌───────────────────┐   I2C (0x42)   ┌───────────────────────────┐
│ bootloader_tool   │◄──────────────►│ bootloader  @ 0x08000000   │
│ (Linux i2c-dev /  │                │ application @ 0x08002000   │
│  CP2112)          │                └───────────────────────────┘
└───────────────────┘
```

## Слои и зависимости

```
app/ ─┐
      ├──► hal/  ──► STM32CubeF1 (CMSIS + LL заголовки)
boot/ ┘     │
      └──► common/ ──► hal/ (только meta.c использует Flash)
```

| Слой | Назначение | Компилируется |
|------|-----------|---------------|
| `platform/` | startup, линкер-скрипты | один раз (OBJECT) |
| `hal/` | регистры: board, flash, i2c, system | дважды (`hal_boot`, `hal_app`) |
| `common/` | CRC, метаданные, фрейминг протокола, типы | один раз (STATIC) |
| `boot/` | валидация образа, I2C OTA, переход в приложение | boot |
| `app/` | эмуляция батареи, обработка команд | app |
| `tools/` | хостовая утилита (нативный GCC) | host |
| `tests/` | модульные тесты (host, с моками) | host |

Разделение `hal`/`common`: `hal` содержит различающийся между образами
код (по `BOOT_BUILD`), поэтому компилируется отдельно для каждого
образа. `common` не содержит `#ifdef` и собирается один раз; в каждом
образе неиспользуемые секции удаляются `--gc-sections`.

## Карта памяти

Подробности — в [flash_map.md](flash_map.md). Кратко (C8T6):

```
0x08000000  Bootloader   8 KB
0x08002000  Application  54 KB  (CBT6: 120 KB)
0x0800F800  Meta 0       1 KB
0x0800FC00  Meta 1       1 KB
```

RAM: `0x20000000`, длина `20K - 16`. Верхние 16 байт
(`0x20004FF0..0x20004FFF`) исключены из стека/кучи. В `0x20004FFC`
приложение пишет магическое число `0x55AA55AA` перед сбросом, что
переводит загрузчик в режим обновления.

## Поток загрузки

1. `board_init()` — HSI 8 МГц, SysTick, LED (+ питание host в boot).
2. Загрузчик проверяет флаг `0x55AA55AA` в `0x20004FFC`.
   - Флаг есть → остаётся в режиме OTA и обслуживает I2C.
   - Флага нет → `app_validate()` (SP/PC/размер + CRC32 образа).
3. При валидном образе `boot_app()` выключает I2C/SysTick, чистит NVIC,
   ставит VTOR и передаёт управление на reset-вектор приложения.
4. Приложение подтверждает запуск (`boot_confirm()`), снимая флаг
   `PENDING`. Если запуск не подтверждён `MAX_BOOT_ATTEMPTS` раз, образ
   помечается невалидным.

## Метаданные (ping-pong)

`MetaConfig` (28 байт) — бинарный контракт между образами. Определение
единственное (`common/meta.h`), размер и смещения проверяются
`_Static_assert`. Метаданные пишутся поочерёдно в две страницы; при
чтении выбирается валидная страница с большим `seq`.

## Особенности, влияющие на поведение

- Обработчики I2C (`I2C1_EV/ER_IRQHandler`) читают регистры напрямую
  (опрос флагов внутри IRQ) — как в исходных версиях; сохранено ради
  таймингов OTA.
- Загрузчик приостанавливает I2C (`i2c_pause()`) на время стирания/
  записи Flash; в приложении это no-op (запись идёт до старта I2C).
