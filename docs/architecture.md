# Архитектура

## Обзор

Проект реализует ACPI-EC: загрузчик + приложение с обновлением прошивки
по I2C (OTA). Поддерживаются четыре цели:

| Цель | MCU | Flash | SRAM | Роль |
|---|---|---|---|---|
| `C8T6` | STM32F103C8T6 | 64 KB | 20 KB | эмулятор батареи |
| `CBT6` | STM32F103CBT6 | 128 KB | 20 KB | эмулятор батареи (стенд OKO) |
| `C011x6` | STM32C011F6P6 | 32 KB | 6 KB | EC + кнопка питания + Stop (стенд) |
| `C031x6` | STM32C031F6P6 | 32 KB | 12 KB | EC + кнопка питания + Stop |

```
Хост (RV1106 / RPi / PC)                STM32
┌───────────────────┐   I2C (0x42)   ┌───────────────────────────┐
│ bootloader_tool   │◄──────────────►│ bootloader  @ 0x08000000  │
│ (Linux i2c-dev /  │                │ application @ 0x08002000  │
│  CP2112) / oko-ec │                └───────────────────────────┘
└───────────────────┘
```

## Слои и зависимости

```
app/ ─┐
      ├──► hal/include + hal/<family> ──► STM32CubeF1 / STM32CubeC0
boot/ ┘     │
      └──► common/ ──► hal/ (meta.c, power_fsm.h — без железа)
```

| Слой | Назначение | Компилируется |
|------|-----------|---------------|
| `platform/stm32f103`, `platform/stm32c0` | startup, линкер-скрипты | один раз (OBJECT) |
| `hal/include` | общие заголовки: board, flash, i2c, system, power | — |
| `hal/f1`, `hal/c0` | регистры и пины выбранного семейства | дважды (`hal_boot`, `hal_app`) |
| `common/` | CRC, метаданные, фрейминг, типы, `power_fsm` | один раз (STATIC) |
| `boot/` | валидация образа, I2C OTA, переход в приложение | boot |
| `app/` | батарея, команды, мост питания `power_task` | app |
| `tools/` | хостовая утилита (нативный GCC) | host |
| `tests/` | модульные тесты (host, с моками) | host |

`common` не содержит обращений к регистрам. `power_fsm.c` — чистая логика,
возвращает приложению упорядоченный список действий; `app/src/power_task.c`
исполняет их через `hal/*/power.c`, `i2c.c`, GPIO и LED.

## Карта памяти

Подробности — в [flash_map.md](flash_map.md). Кратко:

```
F103 C8T6:  0x08000000 boot 8K, 0x08002000 app 54K,  Meta 0x0800F800/0x0800FC00
F103 CBT6:  0x08000000 boot 8K, 0x08002000 app 120K, Meta 0x0801F800/0x0801FC00
C011/C031:  0x08000000 boot 8K, 0x08002000 app 20K,  Meta 0x08007000/0x08007800
```

Флаг входа в OTA — линкер-символ `__ec_update_flag` (F103 `0x20004FFC`,
C031 `0x20002FFC`); верхние 16 байт RAM исключены из стека.

## Поток загрузки

1. `board_init()` — тактирование, SysTick, LED. На C031 загрузчик **не
   трогает PWR_EN**: линию держит внешний pull-up.
2. Загрузчик проверяет флаг `0x55AA55AA` в `__ec_update_flag`.
   - Флаг есть → остаётся в режиме OTA и обслуживает I2C.
   - Флага нет → `app_validate()` (SP/PC/размер + CRC32 образа); верхняя
     граница SP — `EC_RAM_TOP` выбранного семейства.
3. При валидном образе `boot_app()` выключает I2C/SysTick, чистит NVIC,
   ставит VTOR и передаёт управление reset-вектору приложения.
4. Приложение подтверждает запуск (`boot_confirm()`), снимая флаг
   `PENDING`. Если запуск не подтверждён `MAX_BOOT_ATTEMPTS` раз, образ
   помечается невалидным.

`BOOT_SELFTEST=ON` (диагностика, по умолчанию выключено) заставляет
загрузчик стереть/записать/прочитать последнюю страницу области
приложения и показать результат LED: PASS — 3 вспышки, FAIL — мигание
100 мс. После проверки приложение не запускается.

## Тактирование

### F103

HSI 8 МГц, SysTick 1 кГц. `millis()` считает миллисекунды.

### C031

- HSI 48 МГц, `HSIDIV=/4` → SYSCLK 12 МГц (после сброса и после Stop).
- SRAM: C011F6 — 6 КиБ (`_estack 0x200017F0`), C031F6 — 12 КиБ
  (`0x20002FF0`); размер задаётся `EC_RAM_SIZE_KB`/`RAM_LENGTH`.
- `HSIKERON=1`: такт HSI для периферии сохраняется в Stop.
- I2C1 kernel clock — **HSIKER** (`CCIPR.I2C1SEL=10`), `TIMINGR` на
  400 кГц при 48 МГц. PCLK (`00`) ломает пробуждение из Stop и занижает
  `tTIMEOUT` в 4 раза.
- RTC и LSE не включаются. В STM32C031 **нет LPTIM**, а RTC не имеет
  wakeup-таймера, поэтому EC не просыпается по таймеру: только кнопка
  (EXTI0) и адрес I2C (`WUPEN`). Идле-таймаут 3 с считается по SysTick,
  пока EC бодрствует, затем вход в Stop.
- После Stop `clock_restore_after_stop()` заново взводит SysTick;
  время сна в `millis()` не входит.

## Конечный автомат питания (C031)

Состояния: OFF, BOOTING, AWAKE, SUSPENDING, SUSPENDED, SHUTTING_DOWN,
REBOOTING, ERROR.

- Кнопка: дребезг 30 мс, short < 1 с, long 3 с (по удержанию), very-long
  8 с, двойное окно 400 мс.
- OFF + short → `PWR_EN=1`, BOOTING. BOOTING ждёт `PWR_GOOD` ≤ 500 мс и
  первый кадр хоста ≤ 30 с; до 3 power-cycle, затем ERROR.
- AWAKE short → запрос SLEEP; long → SHUTDOWN (через 5 с — рубильник);
  very-long → немедленный `PWR_EN=0`; double → REBOOT (`T_off` 1 с).
- SUSPENDED short → импульс `HOST_WAKE` 150 мс → AWAKE.
- Тишина хоста 3 с → SUSPENDED (`flags.b3`); любой валидный кадр → AWAKE.
- `POWER_ON_RESTORE=0`: после подачи питания хост ждёт кнопку.
- Backup-регистры PWR хранят `pwr_en_wanted`, состояние и число
  boot-попыток; после `NVIC_SystemReset` EC не меняет питание хоста.
- IWDG не включается: он считает и в Stop и сбрасывал бы EC во сне.
- Линковка ELF для ST-Link использует `-Wl,--nmagic`: иначе GNU ld
  (binutils 2.45) кладёт ELF-заголовки в первый PT_LOAD и `flash-app`
  затирает загрузчик/пишет ниже 0x08000000.
- Для GDB в `power_task.c` есть зеркала `g_host_state`, `g_last_event`,
  `g_last_wake_src`, `g_wake_count` (без I2C-мастера это основной канал
  проверки).

| Паттерн | Состояние |
|---|---|
| 1 вспышка / 2 с | OFF |
| двойная вспышка | BOOTING |
| 500 мс | AWAKE |
| 2 с | SUSPENDED |
| 100 мс | ERROR |
| выключен | Stop |
| N вспышек | последний жест (1 short, 2 long, 3 very-long, 4 double) |

## Метаданные (ping-pong)

`MetaConfig` (28 байт) — бинарный контракт между образами. Определение
единственное (`common/meta.h`), размер и смещения проверяются
`_Static_assert`. Метаданные пишутся поочерёдно в две страницы; при
чтении выбирается валидная страница с большим `seq`. На C031 страница
2 KB, запись — четыре double-word с дополнением `0xFF`.

## Особенности, влияющие на поведение

- Обработчики I2C читают регистры напрямую (опрос флагов внутри IRQ) —
  сохранено ради таймингов OTA. На C0 один вектор `I2C1_IRQn`.
- `i2c_pause()` (PE=0 + маска `I2C1_IRQn`) приостанавливает I2C на время
  стирания/записи Flash и в загрузчике, и в приложении; `i2c_resume()`
  заново конфигурирует периферию. Инвариант «операция с Flash XOR живой
  I2C» больше не зависит от порядка вызовов в `main()`.
- Bus-watchdog (`app/src/bus_watchdog.c`) каждый тик проверяет, что при
  `PE=1` и незавершённой транзакции `tx_pos`/`rx_count` продвигаются;
  простой дольше `POWER_BUS_HANG_MS` (15 мс) вызывает `i2c_recover()`.
- Перед `PWR_EN 1→0` прошивка отпускает `HOST_WAKE` и только затем
  выключает I2C: исключается back-power через ESD-диоды хоста.
